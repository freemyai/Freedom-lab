## 三、实施中发现并修复的问题

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | Freedom 模型分析题 6/8 空答 | `FROM gguf` 用 GGUF 内嵌模板，与 Ollama thinking 分割不兼容，答案全进 reasoning | Modelfile 加 `RENDERER qwen3.8` + `PARSER qwen3.5`，8/8 全过 |
| 2 | 沙箱「无外网」实际联网 | `docker_extra_args` 的 `--network=none` 不被 Hermes 消费 | 改用原生键 `terminal.docker_network=false` |
| 3 | 备份 3.6G 且漏掉记忆本体 | tar --exclude 裸名不生效；PG 数据在 ~/.pg0 未纳入 | find 清单法 + 显式备份 ~/.pg0，150M |
| 4 | subagent 压缩超时+假死事故 | 压缩 timeout=120s 对 27B 本地模型必然不够；压缩/委派都走 freedom+thinking；stale 检测误杀思考期 | 压缩与委派钉到 stock + reasoning_effort=none + 900s；stale 窗口 1800s |
| 5 | sudo 不可用 | 无免密 sudo | Ollama 用户级启动脚本替代 systemd |

## 四、性能实测

| 指标 | 数值 | 说明 |
|---|---|---|
| 生成速度 | 4.5-8 t/s | 27B Q4 在 GB10 上接近带宽物理上限（~16 t/s 理论值） |
| Prefill | 80-200 t/s | |
| Hindsight consolidation | ~20s/条记忆 | 本地 qwen 做事实抽取 |
| 压缩（修复后） | reasoning 关闭，~22s/短任务 | |

**性能结论：** 单聊够用；多 subagent 长任务痛苦。提速路线（按性价比）：
1. Speculative decoding / MTP（draft 模型已在 HF 仓库里，2-3x）
2. SGLang/vLLM 替换 Ollama（文档 §39 Phase 7 原定计划）
3. 小模型跑杂活（Hindsight extraction 可换 4B）

## 五、网络受限环境绕过方法（本机实测有效）

| 资源 | 问题 | 解法 |
|---|---|---|
| github.com | 被墙 | api.github.com 直连可用；release 资产走 API octet-stream + Range 分片 |
| git clone | 被墙 | 单命令作用域 `url.https://gh-proxy.com/...insteadOf` |
| huggingface.co | 被墙 | HF_ENDPOINT=hf-mirror.com；CDN 支持 Range 并行 |
| pypi.org | 极慢（0.5MB/s） | UV_INDEX_URL=清华镜像（28MB/s） |
| registry-1.docker.io | 被墙 | docker.m.daocloud.io（官方 library 镜像在白名单） |
| ollama.com/install.sh | 307 到 github | 改用 api.github.com asset 直接下载 |

工具：`scripts/parallel-download.sh`（N 路分片 + 断点续传）

## 七、已知限制

1. Ollama 是用户级进程，**机器重启后需手动跑** `scripts/start-ollama.sh`

3. Hermes 内置记忆召回靠注入 MEMORY.md 头部，长记忆主力是 Hindsight
4. freedom 模型 tool calling 可靠性未做全量 benchmark（T 系列），暂不任 controller
